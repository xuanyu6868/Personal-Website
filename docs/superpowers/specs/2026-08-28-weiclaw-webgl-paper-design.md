# WeiClaw WebGL 真实纸张系统设计

日期：2026-08-28

状态：已确认

适用范围：个人作品集中的 `03 — WEICLAW` 单屏项目场景

## 1. 目标与边界

本次重做只替换 WeiClaw 场景中“书页本体、页面内容合成和翻页运动”这一层。现有全屏视频背景、顶部导航、右侧项目进度点、全屏滚动、左侧项目介绍、图片预览 Overlay 和其他项目页面均保持原有行为。

最终视觉必须同时满足两种状态：

- 静止时，截图、文字、纸张纹理和光影属于同一个弯曲表面，不能看出“网页截图贴在纸上”的分层感。
- 翻页时，书脊固定、外缘先抬起、弯曲向书脊传播，移动页始终形成连续的 C 型或轻微 S 型曲面，不能再是一张绕轴旋转的硬平面。

书本尺寸与位置沿用当前方向：约占视口宽度 50%～58%，中间偏右，四周保留大量山景。背景不增加大面积黑色蒙层。

## 2. 已确认的实现选择

采用方案 A：在现有 React + TypeScript 项目中使用原生 WebGL 渲染可变形纸张网格。

选择原因：

- 项目现有 `InteractivePortrait` 已具备原生 WebGL 的着色器、纹理、ResizeObserver、IntersectionObserver、按需 RAF 和完整资源清理模式，可以复用同一技术习惯。
- 当前依赖中没有 Three.js；本方案无需为一张纸引入完整 3D 引擎。
- 网格顶点可随拖动进度实时更新，图片、文字、纸纹和光影会共同沿曲面变形，能从根本上解决刚性 `rotateY` 的问题。
- 可把几何计算拆成纯函数，便于用单元测试验证书脊锚定、弯曲传播、角部滞后和数值稳定性。

现有 CSS 书本仍承担硬封皮、纸页厚度、底部接触阴影和非 WebGL 降级外观；WebGL 画布只覆盖左右可见纸面与翻动页，不重新绘制整个网站或背景。

## 3. 组件与模块边界

### 3.1 `components/WeiClawBook.tsx`

保留为交互编排层，职责包括：

- 当前跨页索引和前后页切换。
- Pointer Down / Move / Up 的拖动状态。
- 点击左右页翻页。
- 图片预览 Overlay、ESC 和点击背景关闭。
- 克制的书本 Pointer Parallax。
- 向渲染层传递当前页、下一页、方向和归一化翻页进度。

它不再直接通过 `.weiclaw-book__turning-sheet { transform: rotateY(...) }` 绘制翻页。

### 3.2 `components/weiclaw/WeiClawPaperMesh.tsx`

React 与 WebGL 的边界组件，包含一个透明 Canvas。职责包括：

- 初始化、更新和销毁 WebGL 渲染器。
- 根据当前跨页加载左右页、移动页正面和背面纹理。
- 接收 `progress`、`direction`、尺寸和可见状态。
- 按需请求单帧渲染，不开启永久循环。
- WebGL 初始化失败时让底层 DOM 纸页继续显示。

### 3.3 `components/weiclaw/createPageTexture.ts`

使用离屏 Canvas 2D 把每一页完整排版烘焙为一张纹理：

- 暖白纸基底与非常克制的纸粒。
- 页码、类型、标题、说明和手写批注。
- 对应的真实 WeiClaw 产品截图。
- 裁切、出血、轻微旋转和局部叠放。

截图不再作为独立 DOM 图片悬浮于纸面之上；它与文字和纸张底色一起进入同一张纹理，随后由同一个网格和同一套光照变形。

字体加载完成后再生成纹理，避免 Canvas 排版与页面字体不一致。纹理只在页面数据、尺寸或 DPR 改变时重建。

### 3.4 `components/weiclaw/paperGeometry.ts`

纯 TypeScript 几何模块，输入为页面方向、翻页进度、网格尺寸和曲面参数，输出为：

- 顶点位置。
- UV 坐标。
- 三角形索引。
- 法线。
- 页面边缘采样点。
- 动态阴影参数。

该模块不访问 DOM 或 WebGL，便于直接测试。

### 3.5 `components/weiclaw/webglPaperRenderer.ts`

封装 WebGL 资源生命周期：

- Shader 编译与 Program 链接。
- 顶点、UV、法线和索引 Buffer。
- 页面纹理上传和释放。
- 静态左右页、移动页正反面、边缘和阴影的绘制顺序。
- Resize、DPR 和透明背景处理。
- Context lost / restored 的安全处理。

渲染器以 WebGL 1.0 兼容的 GLSL 和 API 为基线，与项目现有原生 WebGL 实现保持一致。曲面法线由 CPU 几何模块生成，不依赖屏幕空间导数扩展。

## 4. 纸张几何模型

### 4.1 网格密度

桌面默认使用约 `40 × 16` 个分段，横向密度高于纵向密度，因为主要变形沿书脊到外缘传播。较窄视口使用约 `24 × 10` 分段。DPR 上限为 2，避免 Retina 屏幕无意义放大填充成本。

每张纸的局部坐标：

- `u = 0`：书脊。
- `u = 1`：页面外缘。
- `v = 0`：页顶。
- `v = 1`：页底。

### 4.2 静态页曲面

左右静态页也使用网格，不是平面矩形：

- `u = 0～0.12` 形成靠近书脊的压缩和凹陷。
- 页面中段较平，但保留轻微鼓起。
- 外缘略微上抬。
- 顶边和底边带轻微、不同步的自然弧度。

这样产品截图即使在未翻页时也会随纸面压缩、弯曲和接受同一套光照。

### 4.3 翻页传播

归一化翻页进度为 `p ∈ [0, 1]`。外缘先响应，书脊最后响应。每个横向顶点使用局部进度：

`localP = smoothstep(start(u, v), end(u, v), p)`

其中：

- `u` 越接近 1，`start` 越早。
- `u` 越接近 0，`start` 越晚，并受到书脊锚定限制。
- `v` 越接近顶部或底部，加入小幅滞后，使页角不与页面中心完全同步。

系统不会给整页应用一个统一旋转角。它会沿 `u` 积分局部切线角度，逐列生成连续曲线：

- `p ≈ 0.2`：外缘抬起，主体仍贴在右页。
- `p ≈ 0.5`：中部越过书心，截面形成明显 C 型，局部可出现轻微 S 型转折。
- `p ≈ 0.8`：大部分纸面已向左展开，靠近书脊的区域仍在压缩和转折。
- `p = 1`：纸张自然铺落在左侧页堆上。

移动页正面和背面使用同一组几何。根据三角形朝向选择对应纹理，不会出现一张正面和一张背面分离运动的问题。

### 4.4 书脊参与

`u = 0～0.12` 是专门的书脊过渡带：

- 最内侧顶点保持锚定，不横向漂移。
- 邻近顶点依次经历压缩、隆起、转折和展开。
- 翻页中段在书脊附近形成更深的接触阴影。
- 翻页结束后，这一带重新贴合另一侧静态页曲面。

这部分保证移动页不是“从中线铰接的一块板”，而是从装订处被带动的柔性纸张。

### 4.5 页面厚度与边缘

单张移动页使用两种手段表达厚度：

- 正反面之间保留极小的法线方向间距，避免完全零厚度的闪烁和纸片感。
- 沿外缘、顶边和底边绘制一条暖灰色的薄边缘带，亮度随视角变化。

静态纸堆、硬封皮和底部页层继续由现有书壳结构承担，使静态和动态状态的层叠关系连续。

## 5. 页面纹理与编辑设计

### 5.1 统一材质

每一页最终只上传一张完整纹理。纸张底色、文字、截图、批注和印刷细节在同一纹理内，因此：

- 靠近书脊时一起压缩和变暗。
- 页面鼓起时一起接受高光。
- 翻动时一起弯曲。
- 纸粒与产品截图共享同一表面，不再出现两套光影。

产品截图会在合成阶段轻微降低屏幕感：小幅压低对比度和饱和度，并叠加非常淡的纸纹与暖色，使其像印刷内容，但不损伤界面可读性。

### 5.2 五种页面布局

页面数据增加明确的 `layout` 和 `crop` 配置，不再复用“标题 + 描述 + 一个规整矩形截图”的模板。

- Dashboard：大图向底部和外侧出血，标题区保留大面积留白，批注压在图像边缘。
- Chat：使用纵向裁切，图片更靠近书脊，局部聊天区域延伸到页面下缘。
- Customer：主截图约占页面 70%，标题不与图片等宽对齐，形成编辑式不对称构图。
- AI Agent：同一真实截图生成主视图与局部细节裁切，形成一大一小的视觉节奏。
- Settings：截图横向展开并向外缘出血，文字区缩小，强调流程和托管策略。

所有版式继续使用现有真实截图资源，不生成虚假的产品界面。可用裁切、出血、轻微旋转和局部叠放增强印刷感；不使用统一圆角卡片、发光边框、HUD、科技网格或装饰性占位框。

## 6. 光照与动态阴影

### 6.1 统一表面光照

Fragment Shader 对纸面纹理整体应用同一套材质：

- 基于曲面法线的暖色漫反射。
- 靠近书脊的柔和暗化。
- 随纸面隆起移动的低强度高光。
- 极淡的程序化纸粒，用于统一纸张和截图，不作为可见装饰资产。
- 对截图区域同样生效的明暗变化。

光照目标是实体纸张，不做 Glow 或金属质感。

### 6.2 翻页投影

移动页下方增加按翻页状态变化的投影。渲染器把移动页顶点沿固定光线方向投影到左右承接页的基准曲面，并在纸面之前绘制半透明 Shadow Mesh；顶点透明度由移动页高度、局部翻页角度和到边缘的距离共同计算，Fragment Shader 对边缘做羽化。

投影状态遵循：

- 起始和落下阶段：投影较宽、较软、透明度低。
- 接近 90°：投影变窄、变深，并向书脊集中。
- 页面越过中心后：投影方向切换到另一侧。
- 页面完全铺落：移动投影消失，只保留纸堆接触阴影。

书脊区域另有一条更深但很窄的接触阴影，用于表达装订处的压缩。

## 7. 交互与动画数据流

### 7.1 拖动

- Pointer Down 时记录书本局部坐标并捕获 Pointer。
- Pointer Move 将横向拖动映射为 `p`，并直接更新网格目标状态。
- 拖动 20%、50%、80% 时分别呈现局部卷起、中部跨越和大部分铺开的不同曲面。
- Pointer Up 时按进度和释放速度共同判断完成或回弹。
- 超过阈值时从当前进度补间到 1，随后才提交新的跨页索引。
- 未超过阈值时从当前进度补间回 0。
- Drag 结束立即释放 Pointer Capture，网站滚动恢复正常。

### 7.2 点击与悬停

- 点击右页触发下一页，点击左页触发上一页。
- 靠近右下角时只增加小幅角部隆起，提示可翻页；不显示夸张的独立卷页图片。
- 静止状态保留轻微页角翘起，但轮廓必须属于完整纸面曲线。
- 点击截图区域仍打开现有大图预览 Overlay。

### 7.3 渲染节奏

不运行永久 RAF：

- Pointer Move、Hover、Resize、纹理完成和动画补间时请求渲染。
- 自动完成或回弹只在补间期间运行 RAF。
- IntersectionObserver 检测场景离开视口后停止动画与绘制。
- 页面不可见时取消未完成帧。

进入场景的书本整体动画继续由现有 Motion/CSS 承担，WebGL 只负责纸面内部的物理形变。

## 8. 无障碍与降级

- `prefers-reduced-motion` 下关闭持续的 Pointer Parallax，点击翻页使用短时、低幅度过渡；页面内容和前后页导航仍可用。
- WebGL Canvas 标记为装饰层并对辅助技术隐藏；组件保留独立的语义化当前页文本、页码和前后页按钮，翻页完成后通过 `aria-live="polite"` 更新当前跨页。
- WebGL 不可用、Context 初始化失败或 Context 丢失时显示底层 DOM 纸页，并使用无卷曲的短过渡；不能让页面空白。
- 不绑定滚轮事件，滚轮始终服务于网站原有全屏滚动。
- 所有 Pointer、Resize、Intersection、键盘监听和 WebGL 资源在组件卸载时清理。

## 9. 测试策略

### 9.1 几何单元测试

在写渲染代码前先建立失败测试，覆盖：

- `p = 0` 和 `p = 1` 的左右落点。
- 书脊最内侧顶点在全过程保持锚定。
- 外缘顶点早于书脊附近顶点响应。
- `p ≈ 0.5` 时横截面非共线，存在明确 C 型或轻微 S 型曲率。
- 顶部、底部角点相对页面中部存在滞后。
- 所有进度和尺寸输入下不存在 `NaN`、无穷值或越界索引。
- 正反翻页互为镜像且 UV 方向正确。

### 9.2 纹理与数据测试

- 五页均配置不同的 `layout`。
- 所有截图裁切矩形位于源图范围内。
- 页面纹理包含标题、页码和对应真实截图。
- 纹理生成失败时返回可显示的纸面降级纹理。

### 9.3 生命周期与组件测试

- 代码不再依赖旧 `.weiclaw-book__turning-sheet` 的刚性 `rotateY` 路径。
- 仅在状态变化或动画期间请求帧。
- 离开视口和卸载时取消 RAF、Observer 和 Pointer 监听。
- WebGL Buffer、Texture、Shader 和 Program 均被释放。
- Reduced Motion 和 WebGL 降级路径存在。
- 没有 Wheel 监听，不影响现有全屏滚动。

### 9.4 浏览器视觉验收

使用当前 Codex 内置浏览器，在同一视口和同一 WeiClaw 场景状态下检查：

- 静止状态：截图随静态纸面弯曲，书脊处同步压缩和变暗。
- 拖动 20%、50%、80%：移动页轮廓、图片内容和阴影同步变化。
- 回弹与完成：从释放位置连续过渡，无跳帧或索引提前切换。
- 正向和反向翻页：正背面纹理方向正确。
- 点击翻页、图片预览、ESC 关闭和背景关闭。
- 窗口 Resize、较窄视口、Reduced Motion 和场景离开后暂停。
- 控制台无 Shader、纹理、Context 或事件清理错误。

参考图与实际截图必须以相同视口并排比较，修正明显的书本尺寸、位置、页缘、书脊、阴影和裁切差异后再验收。

## 10. 性能预算

- 桌面网格三角形数量保持在约 1,280 个以内，移动端约 480 个以内。
- 页面纹理只缓存当前跨页、相邻页和移动页需要的集合。
- Canvas 实际像素 DPR 上限为 2。
- 拖动时只更新必要的顶点 Buffer 和阴影参数，不重建纹理。
- 不产生持续无意义 RAF。
- 场景不可见时不提交绘制。

## 11. 实施顺序

1. 用测试锁定纸张几何、书脊锚定、角部滞后和数值稳定性。
2. 建立离屏页面纹理生成器，并把五页改成不同 Editorial Layout。
3. 建立 WebGL 渲染器，先完成静态左右曲面和统一材质。
4. 接入移动页正反面、C/S 曲面翻页、边缘厚度和动态投影。
5. 替换旧刚性翻页层，接入现有拖动、点击、预览和跨页状态。
6. 完成 Reduced Motion、WebGL 降级、Resize、可见性暂停和资源清理。
7. 在浏览器中捕获静止、20%、50%、80% 和落页状态，与参考图并排比较并迭代。

## 12. 完成标准

只有同时满足以下条件才视为完成：

- 静态截图中，产品画面明显属于弯曲纸面，不再像独立矩形 PNG。
- 翻页中，纸张轮廓有连续曲线，顶部和底部边角存在自然滞后。
- 书脊附近参与压缩、隆起、转折和展开，没有硬铰链感。
- 图片、文字、纸纹、高光和阴影共同变形。
- 动态投影随翻页角度改变，翻至中段时窄而深，铺落后自然消失。
- 移动页有可辨识的正面、背面和薄边缘，且与静态纸堆层叠连续。
- 页面版式具有出血、裁切和不对称的 Editorial Design 节奏，不再是五页同模板的 PPT。
- 网站背景视频、导航、项目进度、全屏滚动和其他项目页面没有回归。
- 自动测试通过，浏览器控制台无错误，视觉对比通过。
